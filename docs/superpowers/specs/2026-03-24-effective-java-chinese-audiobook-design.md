# Effective Java 中文收听优化转换设计

## 概述

将 `Effective_Java_Raw.epub` 转换为中文版 EPUB，优化语音收听体验，并通过全量验证发现问题以驱动现有 Skills 迭代优化。

## 目标

1. 生成中文版 EPUB，适合语音收听场景
2. 智能处理图片（代码截图 OCR、架构图描述）
3. 复用原始封面（用户确认后）
4. 全量验证并收集 Skill 优化建议

## 详细设计

### 1. 封面处理决策

```
检查是否有用户指定的封面图片？
   ├─ 是 → 使用指定封面
   └─ 否 ↓

检查原始 EPUB 是否有封面图片？
   ├─ 是 → 提示用户确认：
   │       "检测到原书封面，是否使用原封面？[Y/n]"
   │       ├─ Y → 使用原封面
   │       └─ n → 走原逻辑（AI 生成/程序化封面）
   │
   └─ 否 → 使用原逻辑：
           ├─ 有 API Key → AI 生成封面
           └─ 无 API Key → 程序化封面
```

**实现要点**：
- 在步骤 2 提前提取原封面并单独保存
- 步骤 7 生成 EPUB 时根据决策使用封面

### 2. 图片智能处理

合并现有 `code_image_ocr.py` 和 `image_descriptor.py`，增强为统一流程：

#### 处理流程

```
Step 1: 过滤检查（现有逻辑保留）
   ├─ 文件名黑名单：二维码、封面、作者、装饰图、emoji、icon 等
   ├─ 文件大小：< 500B 跳过
   └─ 图片尺寸：< 50x50px 跳过
   ↓

Step 2: 智能分类（视觉模型）
   返回图片类型：
   - CODE_SCREENSHOT（代码截图）
   - TABLE_IMAGE（表格图片）
   - TEXT_SCREENSHOT（文本截图）
   - DIAGRAM（架构图/流程图）
   - CHART（统计图表）
   - OTHER（其他有意义图片）
   ↓

Step 3: 分类处理

   CODE_SCREENSHOT:
     1. OCR 提取代码 → ```java 代码块
     2. 生成代码说明 → > 【代码说明】...
     3. 输出：代码块 + 说明引用块

   TABLE_IMAGE:
     1. OCR 提取表格 → Markdown 表格
     2. 生成表格说明 → > 【表格说明】...
     3. 输出：表格 + 说明引用块

   TEXT_SCREENSHOT:
     1. OCR 提取文本 → 纯文本段落
     2. 无需额外说明

   DIAGRAM / CHART / OTHER:
     1. 生成语音友好描述
     2. 保留原图片 + 添加引用块描述
```

### 3. 验证策略

#### 阶段 1: 中间验证（转换过程中）

| 步骤 | 验证内容 | 方式 |
|------|----------|------|
| EPUB → Markdown | 内容提取完整性 | 抽样 3-5 章 |
| 图片 OCR | 代码提取准确性 | 抽样 5 张 |
| 翻译 | 翻译质量 | 抽样 2-3 章 |

#### 阶段 2: 最终全量验证（EPUB 生成后）

**验证维度**：

1. **结构完整性**
   - 原版章节数 vs 新版章节数
   - 原版图片数 vs 新版图片数（含 OCR 替换）
   - 目录层级是否一致

2. **内容一致性**（逐章比对）
   - 段落结构比对（段落数、列表项数）
   - 图片引用比对（位置、数量）
   - 差异分类（正常差异 vs 异常差异）

3. **特殊处理验证**
   - 封面：确认使用了原封面
   - OCR 代码：全量检查代码块语法
   - 翻译：确认技术术语保留正确

**输出**：
- 全量验证报告（Markdown 格式）
- 差异详情列表
- 异常问题列表（需人工确认）

#### 阶段 3: 反思与 Skill 优化收集

基于验证结果记录：
1. 现有 Skill 的不足之处
2. 本次手动处理的特殊场景
3. 可固化为 Skill 的新能力
4. 优先级排序

> **注意**：全量比对是 Skills 建设期的临时质量保障手段，用于发现问题并驱动迭代优化。随着 Skills 成熟后可逐步淡化。
