# Markdown Format Cleaner

清理 Markdown 文件的格式问题，使文档结构规范、整洁。**纯格式修复，不改变任何内容含义。**

## 核心原则

**仅修复格式，不改变内容。** 所有修改仅限于空白、缩进、标记符号等格式层面，不得改变任何文字内容、段落顺序或语义。

## 输入要求

标准 Markdown 目录结构，通常来自 `markdown-content-enhancer` 的输出：

```
$原文件名_markdown/
├── _enhanced/              # 输入目录
│   ├── 01_章节.md
│   ├── 02_章节.md
│   └── ...
├── images/
└── ...
```

也可直接处理源目录（未经增强的原始 Markdown）。

## 输出

```
$原文件名_markdown/
├── _cleaned/               # 输出目录（新增）
│   ├── 01_章节.md       # 已清理
│   ├── 02_章节.md       # 已清理
│   └── *_report.md      # 处理报告
├── _enhanced/              # 不修改
├── images/                 # 不修改
└── ...
```

> 源文件始终不会被修改，所有处理结果输出到 `_cleaned/` 子文件夹。

## 格式修复规则

### 1. 空行规范化

- 连续 3 行及以上空行 → 压缩为 2 行空行
- 文件开头的空行 → 删除
- 文件末尾保留且仅保留 1 个换行符

### 2. 列表缩进统一

- 无序列表（`-`、`*`、`+`）→ 统一使用 `-` 标记
- 嵌套列表缩进 → 统一为 2 空格
- 修复列表项之间不一致的缩进层级

### 3. 代码块修复

- 未闭合的代码块 → 补全 ``` 标记
- 代码块前后缺少空行 → 补充空行
- 嵌套代码块标记不匹配 → 修复
- **未包裹的代码段落** → 用 ``` 标记包裹。识别特征：
  - 连续 3+ 行包含函数定义（`void`、`def`、`function`）、赋值语句、控制流（`if`/`for`/`while`）、注释（`//`、`#`）、花括号 `{}`、分号结尾等
  - 包含 SQL 语句（`SELECT`、`UPDATE`、`INSERT`、`CREATE`）
  - 包含伪代码特征（驼峰命名函数调用如 `GetConnection()`、`.pop()`、`.Send()` 等）
  - 如能识别语言类型，添加语言标记（如 ```java、```sql）；否则使用无语言标记的 ```
- **代码缩进修复**：EPUB/PDF 转换后代码缩进经常丢失，Agent 应根据代码结构恢复合理缩进：
  - 花括号 `{` 后的内容增加一级缩进（使用 4 空格）
  - 花括号 `}` 前减少一级缩进
  - 函数体、循环体、条件分支内的语句应有缩进
  - 注释与其描述的代码保持同级缩进
  - 对于 Python 等缩进敏感语言，根据 `def`/`class`/`if`/`for`/`while` 等关键词推断缩进层级
  - 对于 SQL，关键词（SELECT/FROM/WHERE/JOIN）各占一行并对齐

### 4. 空白段落清理

- 仅含空白字符的段落 → 删除
- 仅含 `---` 分隔线且前后无实质内容的段落 → 删除
- 连续多个分隔线 → 保留一个

### 5. 标题格式规范

- 标题前后缺少空行 → 补充空行
- `#` 与标题文字之间缺少空格 → 补充空格
- 标题层级跳跃（如 H1 直接到 H3）→ 记录在报告中，由 Agent 判断是否需要修复

### 6. 表格格式规范

- 表格前后缺少空行 → 补充空行
- 表格分隔行格式不规范 → 修复为标准 `|---|---|` 格式

### 7. 行尾清理

- 行尾多余空格 → 清除
- 行尾多余制表符 → 清除

### 8. 图片引用检查

- 检查 `![](path)` 中的图片路径是否指向存在的文件
- 无效引用 → 在报告中记录警告（不删除引用）

---

## 严格约束

**以下内容不得修改：**
- 段落文字内容
- 标题文字内容
- 列表项文字内容
- 引用块内容（包括 `> 【图片描述】`、`> 【代码说明】`、`> 【表格说明】` 等）
- 链接文字和 URL
- 代码块内部内容
- 图片 alt 文字和路径
- 段落顺序
- 任何语义层面的内容

---

## Agent 处理流程

当 Agent 使用此技能处理文件夹时：

1. **确定输入目录**：优先从 `_enhanced/` 读取，若不存在则从源目录读取
2. **创建输出目录**：`_cleaned/`
3. **逐章节处理**：
   - 读取章节文件
   - 按上述规则逐项检查和修复格式
   - **修正图片路径**：确保图片引用路径相对于输出子目录正确（如 `./images/` → `../images/`）
   - 记录每项修复的统计信息
   - 写入 `_cleaned/` 目录
4. **生成处理报告**：记录修复统计、标题层级警告、无效图片引用等
